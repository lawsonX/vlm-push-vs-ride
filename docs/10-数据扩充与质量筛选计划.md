# 10-数据扩充与质量筛选计划（2026-10-10）

> 背景：新设备标注反馈——旧池 475 张未标帧质量差（混入交通安全宣传、电动车广告图），
> 场景匹配度低。lawson 指示：我来（联网设备）找和筛一批新数据，做好了手动搬到新设备。
> lawson 的两条建议：①单人监控轨迹数据集抽帧；②本地 VLM + YOLO 做筛选。

## 三线并行

### 线 1：旧池 VLM 质检（最快出成果，GPU 已恢复）
对全部 11229 帧跑本地 VLM（Qwen2.5-VL-7B，fp16，无 NaN 问题）质量/场景四问：
1. 真实监控/街面画面 vs 广告/宣传片/教学/摆拍
2. 有无自行车/电动车/摩托车
3. 人+两轮车活动（骑/推/站/无）
4. 清晰度
产出：逐帧质检 jsonl → 过滤规则出「可用池」+「推行疑似排序」。预计 1.5~2 小时。

### 线 2：新数据源下载（后台）
| 数据集 | 内容 | 价值 | 获取 |
|---|---|---|---|
| VisDrone2019-VID | 无人机监控，含标注（pedestrian/bicycle/motorbike/tricycle） | 单人轨迹+两轮车精确框；缺点：俯视视角 | aiskyeye（国内可达） |
| MOT17/20 | 街面固定监控视角 | 视角最匹配，但自行车少 | motchallenge（慢） |
| B 站继续挖 | 街面监控实录 | 视角最真实；需 VLM 质检挡广告 | webbridge+yt-dlp（已验证） |

### 线 3：几何+质量硬过滤（YOLO，CPU）
人车同框、人框占比 1~15%（太远/太近都不要）、分辨率下限、去重（感知哈希已有脚本）。

## 交付物
- `new_pool/`：筛选后的帧 + manifest（含 VLM 答案、分数、YOLO 几何）
- 更新标注池排序给新设备标注 UI
- 筛选管线脚本入库（vlm_qc.py 等）

## 决策记录
- 用 7B 而非 3B 做质检：3B 有 fp16 NaN 帧问题（17%），质检要全覆盖，7B 免疫
- 云端 API 备选：本地 VLM 挂了再切 dashscope（已验证 37 秒筛 475 帧）
