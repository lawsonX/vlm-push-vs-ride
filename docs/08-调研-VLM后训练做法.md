## 一、视觉编码器到底冻不冻（对应你视频里的问题）

社区分两派，且都有系统实验撑腰：

| 做法 | 代表 | 结论 |
|---|---|---|
| 指令微调时冻结 ViT | LLaVA-1.5、InstructBLIP | 经验上够用，尤其数据量中等时 |
| 两阶段都联合优化 | InternVL、Qwen-VL | 大规模数据下更强 |
| **数据量决定** | Cambrian-1（23 种视觉骨干的系统实验） | 对齐数据少时冻结更好；数据量上到 120 万+ 后解冻普遍受益 |
| 上下文感知视觉微调 | CoVFT（2026-03） | 7B 模型上用专门方法微调 ViT，平均成绩超过 13B 冻结基线；ViT 不到 5% 参数但潜力大 |
| 细粒度空间任务 | OpenVLA（机器人） | 冻结 ViT 的典型做法在需要精细空间感知时**不够**，必须解冻——因为要读的细节（如零件位置）预训练 ViT 没编码 |

**对咱们的直接推论**：
- 我们的数据量（50~500 条）属于「小数据」，主流建议是**冻结 ViT、练语言侧**——支持 E2（语言 LoRA）为主力
- 但我们的任务恰恰是「细粒度空间感知」（脚在哪、屁股坐没坐），和 OpenVLA 的处境类似——**E3（视觉 LoRA）不是可选项，是关键对照**：如果 E3 明显优于 E2，说明预训练 ViT 确实没编码「人车接触关系」这类特征
- E4 全量微调 0.8B 时 lr 要用 2e-5 级别（见下面超参数），我脚本默认 1e-4 是给 LoRA 的，全量得降

## 二、超参数参考（多个公开配方的交集）

- 全量指令微调：lr 1e-5 ~ 2e-5，1~2 epoch，batch 16~128（FAQ-IT/InternVL-X/MG-LLaVA 都是这个区间）
- LoRA：lr 2e-4，rank 16~64（TB-Bench 交通行为数据集：rank 64、lr 2e-4、冻 ViT 和 LLM 本体只练 connector+LoRA——和我们的场景最接近）
- 视觉预训练/对齐阶段才用 1e-3 这种大 lr，指令微调阶段千万别
- 通用规律：1~2 个 epoch 就够，多了过拟合（VLA 那种 27 epoch 是特例，不通用）

**修正**：train_sft.py 加 --mode full 时自动把默认 lr 降到 2e-5，或实验表里显式标注。

## 三、幻觉的后训练治理（直接对应我们的 H3 发现）

这条线 2025-2026 很热，和我们的「编造证据」发现精准对上：

1. **SFT 先行，DPO 收尾**是标准两段式（多篇一致）。
2. **难例偏好对（hard preference pairs）是关键**：被拒样本要「语言上合理但视觉上无依据」——这正是我们场景的写照：模型答「骑行」并编造「脚踩踏板」，就是典型的 plausible-but-unsupported。来源：Grounded Post-Training with Hard Examples（2026-08），DPO 后比 SFT 基线胜率提高 6.2~8.2 个百分点，且不损伤通用能力。
3. **图像对比偏好对**：同一句话配「原图 vs 编辑过的图」做对比（V-DPO、IC-VCO）。IC-VCO 还专门提出「精确语义扰动」生成难负例。**这就是我们「合成数据」方向的理论依据**：把推行图里的人改成坐姿 → 配对图对比。
4. **在线/策略内偏好数据（on-policy）**：OPA-DPO 指出用模型自己生成的错误回答当被拒样本更有效。**我们手里已经有现成的**：推行图上 5 个模型的错误回答+编造的观察文本，直接能组装偏好对。
5. 注意力监督（ADAPT）：交叉注意力锚点可以可视化「模型在看哪」——和我们 M5 注意力分析互为印证。

## 四、立刻可用的升级（加入实验矩阵）

- **E8（新，DPO 轮）**：在最佳 SFT 检查点上做 DPO。偏好对来源两个：
  - a) 现成数据推行图上模型的错误回答（on-policy 被拒）vs 正确标签（人工选定）
  - b) 合成对比图（见下）
  预期回答「为什么 SFT 之后还要 DPO」：SFT 教概念，DPO 压「编造证据」倾向
- **E9（新，合成对比数据）**：图像编辑生成「同景推/骑对」：
  - 路线 A（copy-paste）：从真实图抠人，改姿势/位置贴回（需要分割模型，CPU 可跑）
  - 路线 B（生成编辑）：等 GPU 空闲用本地扩散模型 inpainting 改脚/坐姿
  - 路线 C（视频抽帧改造）：连续帧天然有「同场景不同姿态」对
- **超参数修正**：E4 全量 lr 2e-5；E2/E3 LoRA lr 2e-4 rank 32（对齐 TB-Bench 配方）

# 第二轮补充（2026-09-30 晚）：合成数据与「最小视觉对比」

## 核心发现：E9 的理论依据找到了

**S-VCO（2025-02）**和**CF-VLM**这条线做的事，和我们的「推/骑配对」是同一个思想，且他们已经系统验证过：

1. **「最小视觉对比」对（Minimal Visual Contrast）**：两张图只在**一个关键语义细节**上不同（如站→坐），配相反的文本答案。S-VCO 用它微调后幻觉下降最多 22%，且视觉依赖越强的任务提升越大
2. **关键教训**：裁剪、加噪声生成的负例图没用——必须是**语义级的精确编辑**（姿态、属性、因果关系的单点修改）。这否定了我们「随便增强一下」的路线，支持「精确改人车接触姿态」的路线
3. **质量控制配方**（可直接抄）：用 DINOv2 特征保证「两张图在细节上确实不同」，用 CLIP 特征保证「两张图整体语义相近」——两步过滤合成对
4. **语言增强**：短标注先用强 LLM 改成对话式问答对（我们已有现成问答模板，可跳过或用云端 LLM 批量改写法）
5. **MixDPO（2026-08，视频版）**的目标一句话说透：「答案应该随视觉证据变化而变化」（input sensitivity）——正是 sg_05_003 上发现的病灶（答案无视自己的观察）的对治目标
6. CF-VLM 的教训也要记住：纯合成有 bias，他们建议 human-in-the-loop 校验——对应我们「合成图也过一遍人工标注」的设计

## E9 落地设计（CPU 可跑版本）

- **工具**：rembg（U2Net 人像分割，CPU 可用）抠人 → 从骑行图抠「坐姿人」贴到推行图的空位（匹配尺度/水平位置）→ 合成「同景骑行版」；反向同理
- **成对产出**：每张人工标注的真实图 → 1 张合成反类图，天然配平（24 推行 → 24 合成骑行 + 24 真实骑行 → 24 合成推行）
- **过滤**：DINOv2/CLIP 相似度双过滤（照搬 S-VCO 配方）
- **用途**：SFT 增广 + DPO 对比对（同 query、两张图、两个答案）
- **domain gap 对策**：合成图单独标 source=synth，评测时真实/合成分开统计；合成样本占比不超过 50%

# 第三轮补充（2026-09-30 深夜）：持续微调与防遗忘

- **双重遗忘（SMoLoRA, 2024-11）**：视觉指令微调时会同时忘掉「视觉理解」和「指令跟随」两种能力，不止传统的那种遗忘。评测指标用 BWT（遗忘率），好的方法能把 BWT 压到 -3%，朴素微调是 -20%~-50%
- **朴素数据回放（Replay）就有六成效果**：在持续学习基准里，简单混入旧数据能把遗忘从 -50% 压到 -22~-27%——支持我们 E6「场景数据 + 通用 VQA 混合」的设计，不用上复杂方法
- **LLaVA-c（2025-06）**：无监督提问正则比回放还稳；逐任务连续微调可以打平多任务混合——但工程复杂，咱们 v1 用混合就够
- **进阶选项（报告里提及即可）**：LoRA-Null / OPLoRA 把 LoRA 适配器初始化在预训练激活的零空间，从原理上避免干扰旧能力；SMoLoRA 双路路由分离视觉适配和指令适配
- **对 E6 的最终设计**：场景数据占 70~90% + 通用 VQA（从 LLaVA 标注里随机抽改写）占 10~30%，训完测 MMMU 子集 + 随机 VQA 回归，BWT 以「骑行召回不跌」为代理指标
