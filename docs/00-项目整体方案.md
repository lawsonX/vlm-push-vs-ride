# VLM「推行 vs 骑行」幻觉调查与微调实践 —— 项目整体方案

> 版本：v1.1（2026-09-30 已获 lawson 拍板，按 5 项决策意见修订）
> 写作约定：全文用大白话，短句，不造词。目标是任何一段都能一眼看懂在干什么、为什么干。

## 1. 我们要研究什么

**场景**：城市监控摄像头视角下，人推着电瓶车或自行车走（推行） vs 骑在车上走（骑行）。

**已知现象**（lawson 实测，qwen3.6 / qwen3.8 开源系列）：

- 人眼一看就是推行，模型几乎 100% 回答「骑行」。
- 但如果先问「人的手、脚、身体分别在车的什么位置」，再追问「是推行还是骑行」，正确率明显上升。

**这说明什么（初步推断）**：模型不是完全「看不见」关键线索，而是「一问即答」的决策路径出了问题。它看到了人和车在动，就直接跳到了训练数据里最常见的答案「骑行」。引导式提问迫使它先检查细节证据，反而答对了。

**这个项目的研究问题，拆成 4 个：**

- RQ1：问题出在**眼睛**（视觉编码器看不清细节）还是出在**脑子**（语言模型部分的判断和对齐有偏）？
- RQ2：训练数据里「骑行」的样本是不是远多于「推行」，导致模型学会了偏置？
- RQ3：哪种微调手段能修好这个问题，同时不把模型的其他能力弄坏？
- RQ4：引导式提问有效，说明「先看证据再下结论」这条路走得通。能不能通过训练，让模型不需要引导也自动这么做？

## 2. 核心假设（每个假设都配了验证方法）

| 编号 | 假设 | 说人话 | 怎么验证 |
|---|---|---|---|
| H1 数据偏置 | 后训练数据里「骑行」远多于「推行」 | 模型见过的世界里，人骑车是常态，推车是罕见事件，所以它闭眼猜「骑行」 | ① 纯文本测试：不给图，只问，看模型先验是不是偏向骑行。② 统计公开训练集（如 LLaVA 系列、ShareGPT4V 等）里 push/bike、ride/bike 相关描述的占比 |
| H2 线索太细 | 区分推行/骑行的关键线索（脚有没有踩踏板、屁股有没有坐上去、腿的姿势）在监控画面里又小又模糊，视觉编码器没提取出来 | 模型不是不想答对，是图里那点细节信息在进语言模型之前就丢了 | ① 用不带语言模型的纯视觉模型（CLIP 做零样本分类："a person pushing a bicycle" vs "a person riding a bicycle"）测同一批图。CLIP 能分清而 VLM 分不清 → 问题在语言侧；CLIP 也分不清 → 问题在视觉侧。② 看视觉编码器的注意力热图，检查它有没有去看脚和踏板的位置 |
| H3 对齐问题 | 后训练（SFT/偏好优化）教模型「快速简短作答」，这种风格让模型倾向用最常见的标签直接回答 | 训练奖励了「秒答」，没人奖励「先看证据再答」 | ① 对比同一模型在不同提问方式下的表现差异（直接问 vs 引导问），差异大 → 说明能力在、只是默认策略不启用它。② 微调实验：在训练数据里加入「先描述证据、再给结论」的样本，看是否修复 |

三个假设不互斥，很可能同时成立。实验设计按「先定位、再修」的顺序来。

## 5. 数据方案

### 5.1 测试集怎么设计（这件事最重要）

不能只搞「推行 vs 骑行」二分类的一堆相似图。要按可能影响的维度**切成格子，每格都有样本**，模型在哪类格子上错得多，一眼就能定位原因。维度初定：

- 车种：自行车 / 电瓶车
- 视角：正面 / 侧面 / 背面 / 斜侧
- 距离：近（人能看清脸）/ 中 / 远（只占几十个像素）
- 光照：白天 / 夜晚 / 逆光
- 遮挡：无遮挡 / 部分遮挡
- 场景：路口 / 人行道 / 小区门口等

目标规模：测试集 300~500 张（抽帧去重后），全部经 Web 标注页面由人工确认标签。另有独立的训练用集。

### 5.2 数据从哪来（按优先级，已实测可达性）

**国内网络可直接下载的（已验证镜像可用）：**

1. **TrafficQA**（HF 镜像 fcxfcx/TrafficQA，约 4000 段交通视频小片段）：车载视角，带交通场景问答标注，作为场景素材。
2. **BDD100K 图片镜像**（HF 镜像 dgural/bdd100k，2 万张带 rider/bicycle/motorbike 相关街景）：行车记录视角，贴近路面监控。
3. **Cityscapes 镜像**（HF 镜像 Chris1/cityscapes，parquet 格式）：有 rider 类别，街景视频序列抽帧。

**需要 lawson 注册账号后才能下载的（后续请他帮忙）：**

- Cityscapes 官网原始数据 + 标注（协议需要个人签名）
- BDD100K 官网完整 10 万图片 + 官方标注文件

**其他来源：**

4. **网络视频抽帧**：B 站/公开视频里搜电动车推行、违停推行等，抽帧。量大、贴近监控画质，仅本地学习用。
5. **合成补充**：用文生图模型生成监控风格图像。可控、便宜，但和真实监控有差距，只作补充和消融实验变量，不作为主力。

### 5.3 人工标注怎么安排（lawson 已拍板：全部走 Web UI）

- **标注方式**：做一个本地 Web 标注页面，所有需要人工确认的图都进这个页面标。
- **页面要素**：大图展示、推行/骑行/不确定 单选、备注框、判断要领说明（看脚有没有踩踏板、看屁股有没有坐上车座、看腿的姿势）、进度显示、标完一键导出。
- **分两个池子**：① 测试集标注池（300~500 张，决定评测是否可信）② 训练集标注池（规模更大，标注格式相同，另外加「证据描述」字段，用于做证据链式训练实验）。
- 页面用 CPU 就能跑，不依赖 GPU。

### 5.4 关键认识

「推行」在公开数据里很少见。这本身就是 H1（数据偏置）的一条旁证，实验里要正式验证它。

## 6. 模型测试矩阵（阶段一：全部走云端 API，不占 GPU）

| 组 | 模型 | 目的 |
|---|---|---|
| A | qwen3-vl-flash、qwen3-vl-plus | 复现你观察到的现象，qwen 系内部对比 |
| B | qwen3.5-omni、qwen3.8-omni | 你重点关注的两个系列 |
| C | qwen-vl-max（闭源最强） | 闭源对齐是不是比开源好 |
| D | 后续可扩：GLM、stepfun、deepseek 系的视觉模型（API 里都有） | 看这是不是行业通病 |

每组模型跑同一套题，题目分三种问法：

1. **直接问**：「图中这个人是在推行还是骑行这辆车？」
2. **引导问**：先问手脚身体位置，再问结论（复现你的发现）
3. **先描述再判断**：「请先描述图中人与车的接触情况，再给出结论」

同时记录：回答文本、是否答对、token 数、有没有编造图中不存在的细节（幻觉检查表）。

## 7. 归因分析方法（回答 RQ1、RQ2）

按便宜到贵的顺序做：

1. **纯文本先验测试**（零成本）：不给图，让模型回答「监控画面里一个人和一辆电瓶车在一起，更可能是在推行还是骑行？」统计倾向。验证 H1 的语言先验部分。
2. **CLIP 对照实验**（CPU 可跑，模型小）：同一批图，CLIP 零样本分类 push vs ride。这一步是「眼睛 vs 脑子」的分水岭实验（见 H2）。
3. **遮挡消融**（云端 API）：把图做处理：只留人、只留车、抹掉脚、抹掉上半身，分别问。看模型答案跟着哪个部位变，定位它实际在看哪。
4. **注意力热图**（需本地 GPU，阶段三做）：对开源模型跑注意力分析，看它「看」图时注意力在脚/踏板/车座上的权重。
5. **训练数据统计**（CPU 可跑）：下载 LLaVA/ShareGPT4V 等公开 SFT 数据，统计骑行 vs 推行的描述占比。验证 H1 的数据部分。

## 8. 微调实验矩阵（回答 RQ3、RQ4，等 GPU 空闲）

### 8.1 基座模型（lawson 已拍板：用小尺寸 + 原生/外挂对比）

| 角色 | 模型 | 特点 |
|---|---|---|
| 主力 1 | **Qwen3.5 2B**（原生多模态） | 原生多模态 = 视觉和语言从一开始一起训练。2B 在 22GB 上全量微调压力小 |
| 主力 2 | **Qwen3.5 0.8B**（原生多模态） | 更小，训练最快，用来快速试配方 |
| 对照 | **Qwen2.5-VL-3B**（外挂视觉模块） | 典型「LLM 挂视觉编码器」架构。用来回答你最开始的问题：原生多模态和外挂视觉模块的模型，微调行为有什么不同 |
| 云端参照 | qwen3.5-omni 系列（API） | 对比微调前后的云上版本表现 |

> 注：Qwen3.5 开源小模型的确切型号和下载地址，到 M6 前逐一核实（以 HuggingFace 镜像 / ModelScope 实际发布为准）。
> 7B 及以上不做全量微调（22GB 显存不够：7B 全量 fp16 + 优化器状态约需 50GB+），最多做 LoRA 类实验。

### 8.2 显存账（解释为什么 7B 不能全量微调）

粗算公式（fp16 权重 + fp16 梯度 + fp32 优化器状态）≈ 每 10 亿参数占 16GB。

- 0.8B 全量：约 13GB → 单卡可行，余量充足
- 2B 全量：约 32GB → 超出，需要梯度检查点 + 8bit 优化器 + 冻结部分层，勉强可行
- 3B 全量：约 48GB → 单卡不可行，做 LoRA 或只训部分层
- 7B 全量：不可行，只做 LoRA

结论：**全量微调实验在 0.8B 上做，2B 做「裁剪版全量」（梯度检查点 + 8bit 优化器），2B/3B 做 LoRA**。这也是实验的一部分：不同大小的模型、不同解冻范围，效果差多少。

### 8.3 实验矩阵

| 实验 | 模型 | 冻结什么 | 数据 | 验证什么 |
|---|---|---|---|---|
| E1 | 0.8B | 只训视觉对齐层（projector） | 场景数据 500 条 | 对齐层够不够修（最小代价方案） |
| E2 | 0.8B / 2B | 只训语言侧 LoRA | 场景数据 500 条 | 不碰视觉能不能修 → 区分眼睛问题还是脑子问题 |
| E3 | 0.8B / 2B | 视觉编码器加 LoRA | 场景数据 500 条 | 解冻 ViT 是否有感知增益（视频观点：感知涨分） |
| E4 | 0.8B | 全量微调 | 场景数据 500 条 | 上限在哪 |
| E5 | 最佳方法 + 数据规模梯度 | — | 100 / 500 / 2000 条 | 数据量与效果的关系 |
| E6 | 最佳方法 + 混合通用数据 | — | 场景 500 + 通用 VQA 若干 | 防遗忘：通用能力掉不掉（视频观点的另一面） |
| E7 | 证据链式训练数据 | — | 先描述证据再给结论的样本 | RQ4：把引导式提问的增益固化进模型 |

另外加一个维度（lawson 提的对比问题）：E1~E4 同样的实验在 **Qwen2.5-VL-3B**（外挂视觉模块）上重复一遍，对比「原生多模态 vs 外挂视觉模块」哪个更好修、怎么修。

### 8.4 每次微调后的评测

- **主指标**：自建测试集（按 5.1 的格子切分）推行/骑行判断准确率。
- **回归指标**：通用 VQA 抽查集（如 MMMU 中取一部分简单题）+ 模型原本擅长的随机题目抽查。防止「治好了这个病，伤了其他地方」。
- **记录**：显存占用、训练时长、数据量。性价比一目了然。

## 12. 风险与已知坑

- **2080 Ti 无 bf16 硬件加速**：所有训练配置统一 fp16（已实测可用）。
- **16GB 内存**：不能做大数据集的内存内处理，pipeline 全部写成流式（边读边写）。
- **「推行」样本稀缺**：公开数据里可能淘不出多少，必要时加大网络视频抽帧和合成数据的比例，并在报告里如实写明数据来源构成。
- **云端 API 与本地开源版不完全等同**：API 测的是官方托管版本，归因和微调用的是本地开源权重，结论适用范围会在报告里注明。
- **Qwen3.5 小模型的确切开放情况**：下载时再核实，如果某个尺寸没开源，用相近型号替代并记录。
- **长程项目管理**：每个里程碑结束写一份阶段小结放进 Kimi 工作区，随时能查看进度。
