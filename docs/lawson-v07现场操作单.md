## 决策一：「踏板 vs 地上」的定义（2 分钟，先做这个）

**背景**：电动车/踏板摩托站立骑时，脚踩在**搁脚板**上（离地面约 15 厘米，中间是平的，不是自行车那种圆脚踏）。金标目前算「踏板」，模型经常答「地上」。A1 在站立骑电动车帧上的真错全卡在这个定义上。

**请从下面三选一**（回复我选项字母即可，或给别的定义）：

- **A.（训练侧推荐）脚踩在车身的任何承脚部位都算「踏板」**——只有脚直接接触地面才算「地上」。理由：区分推行/骑行的物理判据就是「脚有没有踩在车的承脚位置上」，与是不是圆脚踏无关；与「地上」互斥清晰，模型好学。
- B. 只有凸起的脚踏（自行车脚蹬、摩托脚踏）算「踏板」，电动车平搁脚板算「地上」。
- C. 这类图一律标「看不清」，不教模型区分。

> 选定后我会把定义写进标注规范文档，数据侧按此统一 v0.7。你标 Q2 时也按这个定义答。

## 决策二：分歧帧复核（15 分钟，盲标 85 张）

**背景**：Qwen3.5-2B（99% 强基座）有 85 张图的探针答案与金标冲突（训练 64 张 + 测试 19 张）。我目检了 7 张：金标错 2 张（雪山/站立骑行标了「有坐」）、2B 错 4 张（清晰坐姿说它「没坐」）、模糊 1 张。**双方都会错，只能人眼裁决**。队列已按优先级排好（data/v07_review_todo.txt）。

**步骤**：

```bash
cd /hdd2/xiaolirui/vlm-push-vs-ride
/hdd2/xiaolirui/conda_envs/vlm-lab/bin/python scripts/probe_app.py \
    --frames-dir datasets/delivery_v02/frames \
    --todo data/v07_review_todo.txt \
    --port 8322
```

浏览器打开 `http://<本机IP>:8322`（远程的话先 `ssh -L 8322:localhost:8322 <本机>`）。

**标注要领**：

1. **盲标**：别看以前标的是什么，按你看到的事实答。每张图两问：
   - Q1 坐没坐在车座上？按 **1=有 / 2=没有 / 3=看不清**
   - Q2 脚踩哪？按 **4=地上 / 5=踏板 / 6=看不清**（按决策一的定义答「踏板」）
2. **顺序即优先级**：前 36 张是赛事/雪山系列（金标最可能错、最需要你裁决）；中间 36 张街景（大概率 2B 错、你扫一眼确认坐姿就行）；最后 13 张无人机小图（看不清就大方按 3/6）。
3. 拿不准一律「看不清」，猜的不算。
4. 图本身有问题（不是监控画面/人车关系看不清/和推行骑行无关）按 **0** 整图作废；人跨坐（坐座上、双脚着地、车静止）按 **7**。
5. A/D 或方向键翻页，N 跳到未答。

**产出**：你的答案自动存进 `probe_labels.jsonl`（在当前目录）。标完告诉我，我做三件事：与现行金标 diff → 把要改的清单交给数据侧出 v0.7 → 跑 `a8_pipeline` 三种子重训出最终模型。
