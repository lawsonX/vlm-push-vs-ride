# 阶段性归因报告（v0.1）：VLM 为什么把「推行」看成「骑行」

日期：2026-09-30
状态：**进行中**。等街景推行标注到位后补最后一块（各模型推行召回率 + 引导式诚实度判决）。
写作约定：大白话，每个结论后面跟证据和可信度。

## 1. 问题定义

监控/街面画面里，人推着电瓶车或自行车走（推行）时，多个 VLM 会答成「骑行」。lawson 原始观察：qwen3.6/qwen3.8 开源系列几乎 100% 答骑行；先引导模型描述人的手脚位置再问，正确率上升。

研究问题：问题出在**视觉**（看不清关键线索）还是**脑子**（决策/对齐有偏）？修法是什么（数据 vs 微调 vs 提问方式）？

## 2. 假设与当前判决

| 假设 | 内容 | 判决 | 关键证据 |
|---|---|---|---|
| H1 数据偏置 | 训练数据里骑行远多于推行，模型没学过「推行」这个概念 | **强支持** | ① LLaVA 55.8 万条预训练标注：提到车的 3637 条里，骑行 430、推行 8（且 8 条逐条检查无一是真推行）→ 真实比例 ≈ 0~2 : 430。② 标注实证：交通事故行车记录仪池 116 张全骑行、0 推行——**真实世界的推行画面在常见数据分布里几乎不存在** |
| H1b 语言先验 | 模型不看图都偏向答骑行 | **不支持（比想象复杂）** | 纯文字提问：「电瓶车+监控画面」两模型 10/10 答**推行**；「自行车+照片」一个答骑行一个答推行。先验随措辞摇摆，不是一律偏骑行 |
| H2 视觉线索弱 | 区分推行/骑行的细节（脚踩哪、屁股坐没坐）太小太糊，视觉特征提取不出来 | **部分支持** | CLIP 在 322 张图上打分：96% 的图「推行 vs 骑行」分差在模糊区间，只有 13 张明显偏骑行、**0 张明显偏推行**。纯视觉模型也缺乏稳定信号（但 CLIP 自带同样的数据偏置，此证据不完全干净） |
| H3 对齐/决策偏置 | 后训练奖励「秒答」，模型把「人+车+移动」直接映射到高频答案「骑行」，还会脑补支持证据 | **待判决** | 旁证：骑行图上的引导式观察文本极其详尽且自信（「脚踩踏板」「他并不是站在车旁」）。判决性实验：看模型在**推行图**上是否 hallucinate 出「坐着/踩踏板」的虚假观察。等街景推行标注 |

## 3. 核心数据表（云端 API，322 张人车同框车载图 + 78 张 web 监控图）

### 3.1 直接问「推行还是骑行」的答案分布（无真值时的分布）

| 模型 | 车载图答骑行 | web 图答骑行 |
|---|---|---|
| qwen3.5-omni-flash | **97.5%** | 进行中 |
| qwen3.8-omni-flash | 87.9% | 进行中 |

| qwen3-vl-plus | 76.7% | 进行中 |

**模式：模型越强越新，越爱答骑行**——与 lawson 在 qwen3.6/3.8 开源系列的观察同向。若 web 推行标注显示真值推行占比高，97.5% 就是旗舰级偏置的实锤。

### 3.2 有真值的准确率（车载图，n=116 全骑行真值）

| 模型 | 骑行召回 |
|---|---|
| qwen3.5-omni | 97.3% |
| qwen3.8-omni | 91.1% |
| qwen-vl-max | 86.6% |
| qwen3-vl-plus | 78.6% |
| qwen3-vl-flash | 67.0% |

注意 flash 只有 67%：它在 1/3 的真骑行图上答推行——**弱模型会过度纠正**。偏置不是单向的。

### 3.3 问法对比（322 张车载图，分布）

| 模型 | 直接问 | 先描述 | 多轮引导 |
|---|---|---|---|
| qwen3-vl-flash | 61.8% 骑行 | 89.4% | 83.9% |
| qwen3.5-omni | 97.5% | 83.9% | 85.1% |

**「引导式提问」不是万能药**：对弱模型反而把答案推向骑行（先描述让模型「越看越像骑行」）；对强模型只是轻微降温。lawson 原始观察（引导能救回推行）很可能只在**真推行图**上成立——判决同样需要推行真值。

## 4. 关键机制推断（当前版本）

综合以上，最可能的故事线：

1. **概念缺失**（H1，主因）：「推行」在训练语料里几乎没有文字锚点。模型不是「看错」，而是**脑子里没有「人在车旁边走」这个候选标签**，于是把画面归到唯一学过的「人+两轮车」类别「骑行」。
2. **证据编造**（H3，待证）：被问到细节时，模型会生成与结论一致的「观察」（骑行图上观察忠实；推行图上是否编造待验）。如果编造成立，说明后训练强化了「自信地给出高频答案+配套理由」的回答风格。
3. **视觉线索弱**（H2，放大器）：监控分辨率下脚/踏板/坐姿的细节信号本来就弱（CLIP 打分佐证），让「概念缺失」的模型更容易直接走捷径。

## 5. 数据工程侧的发现（本项目独有）

- **推行画面获取难度实测**：交通事故行车记录仪池 116 张 0 推行；必应开放图片搜索杂质率 97%；搜狗精准关键词命中率 56%；新闻内嵌监控原图质量最高但反爬严。最终用「场景推测 → 精准关键词 → YOLO 预筛 → 人工确认」链路解决。
- **推行的真实高发场景**：盗窃推行、推电动车进电梯/楼道、没电推行、共享单车运维调度、违停推移、过马路推行。这批场景词可直接复用于任何后续数据扩充。
- **标注 UI 实战反馈**：需要「无效/其他」按钮（静止摆放、搬动装车等噪声类），已加（按 4）。

## H3 判决：支持，且发现了完整的错误链

**铁证案例 sg_02_019**（真值=推行：行人推行自行车过斑马线，画面远、人小）：
- 4 个模型的直接问全部答「骑行」
- 引导式观察**编造了细节证据**：「他的双脚位于脚踏板上，正踩在左右两侧的脚踏板上」「他明显是坐姿骑行」——画面里根本不可能看清这些
- qwen3.5-omni 的观察更干脆：「双脚都踩在脚踏板上，身体坐在座位上，正在骑行通过人行横道」

**对照案例**（sg_02_016/029/04_000/04_015，模型答对的推行图）：观察文本都诚实描述了「双脚着地、站在车旁、没有坐在车座上」。

**错误链成型**：画面线索模糊（H2）→ 「人+两轮车」先验直接给出高频答案「骑行」（H1）→ 模型生成与该答案一致的虚构细节「脚踩踏板、坐在座上」（H3 的证据编造）→ 虚构证据反过来「确认」了错误答案。三个假设不是互斥的竞争对手，是同一条装配线上的三道工序。

## 对 lawson 原始观察的修正

「引导式提问能提高答对率」**不普遍成立**：在最弱的模型（qwen3.5-omni）上，引导反而更糟（44% < 56%）——因为引导给了它更多编造证据的机会。引导式有效的必要前提可能是：模型的观察能力本身诚实（flash 在多数推行图上观察诚实，引导与直接问相当）。

（注：n=9 仍偏小，且含若干电梯简单场景；lawson 继续标注中，数字会进一步夯实。）

## 难例分布（直接问误判的推行图）

- **sg_02_019**（斑马线推行，人小距离远）：5/5 模型全错——最具代表性的失败案例
- **sg_05_003**（黄衣男子路口跨着自行车一脚着地）：3 模型错。这张是边界案例（跨骑滑行，屁股没落座），lawson 判推行合理
- sg_02_016、sg_04_024：只有 qwen3.5-omni 错

**规律：目标越小越远，失败越普遍**——和格子维度「距离」直接对上。

## 新发现：答案可以无视模型自己的诚实观察（H3 的加强版）

sg_05_003 上 qwen3.5-omni 的「先描述」观察**完全诚实**：「右脚站在路缘石上支撑」「站立在自行车旁边」「短距离推行」——但**最终答案仍然写「骑行」**。说明结论不是从观察推导的，是先验直接生成的；观察文本有时只是结论的「装饰」。这比「编造证据」更深层：**模型已有的诚实视觉阅读能力会被答案生成环节覆盖**。

## 对微调实验的意义（M6 设计输入）

1. 如果问题只是「不知道推行这个概念」（H1），那么**少量推行样本的 SFT 应该快速起效**——直接答格式（E1~E4）验证
2. 如果是「观察诚实但答案环节覆盖观察」（上面新发现），那么需要**证据链格式**（E7：先证据后结论）把观察环节固定进答案路径
3. qwen3.5-omni（原生多模态）反而最差——「原生 vs 外挂」对比实验（Qwen2.5-VL-3B）更有看头了
