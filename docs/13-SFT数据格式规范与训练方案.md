## 1. 一句话方案

用人工金标数据做监督微调（SFT），方法用 LoRA（只训一小部分参数），基座模型用 Qwen2.5-VL-3B。先把最小闭环跑通，再谈扩展。

## 2. 为什么是 SFT、为什么是 LoRA（决策理由）

- **为什么 SFT 不是 RL（强化学习）**：模型现在连基本判断都做不对，强化学习拿不到可靠的打分信号。我们有几百张人工确认的金标，直接拿来教它是常识路线。RL 留到 SFT 之后当进阶实验（见第 7 节实验 A5）。
- **为什么是 LoRA 不是全参数微调**：金标只有几百张量级，全参数微调必然过拟合，还浪费显存。LoRA 够用且便宜。
- **LoRA 会不会不如全参数微调**：2025 年 9 月 Thinking Machines 发表了《LoRA Without Regret》，系统对比了 LoRA 和全参数微调，结论对我们的场景非常有利，要点如下：
  1. **中小规模训练数据下，调好参数的 LoRA 和全参数微调效果一样好**。我们的几百到几千张数据正处在这个区间，选 LoRA 不用后悔。
  2. **LoRA 必须加在全部线性层上，尤其是 MLP 层**（gate_proj、up_proj、down_proj）。只加在注意力层是老做法，效果明显差。这条直接纠正了网上大部分教程。
  3. **LoRA 的学习率要用全参数微调的 10 倍左右**（例如全参数用 2e-5，LoRA 就用 2e-4）。学习率恒定比衰减到零好——衰减太快会让模型还没学完就停止进步。
  4. **批次别太大**：有效批次 32 以内效果最好。LoRA 对大批次的容忍度比全参数微调低。
  5. **排序（rank）按任务选**：SFT 用 16~32 起步就够；以后做 RL 甚至 1~32 都够。
  6. alpha 直接取 2 倍 rank，不用单独调。

## 3. 训练数据格式规范

### 3.1 基本单元：多轮对话，loss 只算回答部分

训练样本是标准的多模态对话格式，问题、图片放用户侧，答案放模型侧。训练时只在模型回答的 token 上计算损失，问题和图片不参与——这是行业标准做法。

### 3.2 一张金标图配多种问法（本规范的核心）

我们之前实证过：**同样的图，直接问会答错，引导问能答对**。如果只按一种问法训练，模型可能只学会"被这样问的时候别答错"，换个问法旧病复发。所以同一张图要配多种问法：

| 格式 | 问法 | 训练目的 |
|---|---|---|
| **direct**（直接问） | "图中这个人是在推行还是骑行这辆车？只回答一个词。"（5 个同义问句随机） | 修"一问即答"的默认错误 |
| **probe_seat / probe_feet**（是非探针） | "这个人有没有坐在车座上？""双脚在地上还是踩踏板？" | 把判断拆成关键证据点，教模型看"坐没坐、脚在哪"（对应 RQ4） |
| **caption**（开放描述） | "请描述一下图中这个人和这辆车的状态。" | 覆盖 lawson 最初发现幻觉的 caption 场景 |
| **chain**（先描述再给结论，单轮） | "请观察这个人的手和脚的位置、身体是坐在车上还是站在车旁，先描述证据，再给结论。" 回答以"证据：…结论：…"的结构书写 | 把"先看证据再下结论"固化成模型习惯（对应 RQ4） |
| **guide**（多轮引导，两轮） | 第一轮问"他的手放在车的什么位置？脚在哪里？身体是坐在车上还是站在车旁？"第二轮问"那么他是在推行还是骑行？" | 教模型在没有引导时也能自己走这条路；同时保留被引导时的能力 |

**探针答案的坑与对策**（2026-10-15 实测发现）：山地车手站立俯冲是标准骑行姿势，"有没有坐在车座上"的答案不能从推行/骑行标签直接推导——按标签推导会有约 230/411 张图答案与图矛盾。对策：`scripts/gen_probes.py` 把探针逐图问云端，**答案与标签推导一致才采用**，不一致的图不出探针样本（宁缺毋滥）。实测 seat 探针仅 179/411 通过验证。

**chain 和 guide 的证据描述，直接用标注人在标注页面写的"判断依据"字段改写**。这是白捡的资源：标注人已经写好了"看脚在地上走路"这类证据，改成"图中的人双脚在地上交替走路，身体站在车的一侧"这样的句式即可（v2 生成脚本做简单的句式整理，不做内容编造）。

### 3.3 问答文本模板（direct 用多个同义问法，防过拟合单一问句）

direct 格式从以下问句中随机选一个（每张图固定随机，可复现）：

1. 图中这个人是在推行还是骑行这辆车？只回答一个词。
2. 观察图中的人和他的车：他是在推行还是骑行？只回答一个词。
3. 这张监控图里，这个人正在推行还是骑行这辆车？只回答一个词。
4. 图中这个人当前是在推车走还是骑车走？只回答一个词。
5. 请判断：图中的人是推行还是骑行这辆车？只回答一个词。

标准答案：推行 / 骑行（一个词，不带标点）。

### 3.4 哪些图进训练集、哪些不进（2026-10-15 按 lawson 拍板收紧）

- **进**：人工标为 push（推行）或 ride（骑行）的图。合成图须额外通过目检，剔除"跨坐"类（人跨坐/站车上、双脚接地、车静止——不算推行，见 15 号文第 0 节）。
- **不进**：标为 unsure（不确定）或 invalid（无效）的图。**一律舍弃，不做负样本**。lawson 标注时就是按"对训练有没有意义"筛的，这两类即脏数据。
- **没有写判断依据的图**：只进 direct 格式，不进 chain/guide（没有证据可教）。

### 3.5 训练集/测试集划分规则（防泄漏，这是铁律）

- **按图划分，不按样本划分**。同一张图的所有问法样本必须全部进训练集或全部进测试集，绝不能拆开——否则等于把考试题提前泄进课本。
- 划分用 frame_id 做哈希，确定性划分，任何人任何机器上重跑结果一致。
- 测试集从金标图里分层抽样：推行、骑行各抽相同数量（默认各 24 张，共 48 张），两类比例 1:1，方便直接读准确率。
- 测试集**永远不参与训练**。每次改数据、改配方，测试集都不动。
- 训练集内部做可选配平（push/ride 1:1 抽样），防模型学到"多数类优先"。

### 3.6 文件格式（jsonl，一行一个样本）

```json
{"frame_id":"...","image":"/绝对路径/xxx.jpg","style":"direct","split":"train","messages":[{"role":"user","content":"<图片占位>图中这个人是在推行还是骑行这辆车？只回答一个词。"},{"role":"assistant","content":"推行"}]}
```

- `image` 写**绝对路径**。新设备上训练前统一用脚本把路径前缀替换成新设备上的实际位置。
- guide 格式的 messages 有 4 条：user → assistant → user → assistant。
- 生成脚本：`scripts/make_sft_data_v2.py`，输入标注结果 `annotations.jsonl` + 帧目录，输出 train/test 两个 jsonl + 统计报告。

## 4. 训练方案（LoRA 配方，按《LoRA Without Regret》执行）

| 配置项 | 取值 | 理由 |
|---|---|---|
| 基座模型 | Qwen2.5-VL-3B-Instruct | 外挂视觉模块的典型代表；3B 跑通管线成本低；7B 等多卡验证后再上 |
| LoRA 目标层 | 语言侧全部线性层（q/k/v/o_proj + gate/up/down_proj） | 论文核心结论：必须含 MLP 层 |
| 视觉部分 | 视觉编码器和 merger 冻结 | 先验证"不碰视觉能不能修好"；解冻视觉留作消融实验 |
| rank / alpha | 32 / 64 | SFT 起步值；消融再试 16 |
| 学习率 | 2e-4，恒定 | 论文：LoRA 学习率 ≈ 全参数的 10 倍；恒定不衰减 |
| 有效批次 | 32（如每卡 8 × 累积 4） | 论文：LoRA 对大批次敏感，32 以内 |
| 轮数（epoch） | 3 起步，看测试集表现增减 | 数据量小，轮数是唯一好用的旋钮 |
| 精度 | bf16（新设备支持）；老机器 fp16 | 老 2080Ti 无 bf16 硬件加速 |
| 损失 | 只算 assistant 回答的 token | 标准做法 |

## 5. 评估方案

每次训练完，在**固定测试集**（3.5 节那 48 张）上测：

1. **三种问法各测一遍**（direct / chain / guide），报推行骑行二分类准确率。
2. **开放描述测试**：问"描述一下图中这个人和这辆车分别在什么状态"，检查描述里有没有把推行说成骑行——这是对最初 caption 幻觉场景的直接回应。
3. 混淆矩阵（推行判成骑行多少、骑行判成推行多少），看错误方向。
4. 参照物：同一测试集上云端 qwen3-vl-plus 的成绩（已有），微调后的模型跟它比。

## 6. 实验清单（按执行顺序）

| 编号 | 实验 | 做什么 | 回答什么 |
|---|---|---|---|
| A1 | LoRA-SFT 主实验 | 三种问法混合数据 + 配方表训练 3B | 最小闭环能不能修好幻觉 |
| A2 | 问法消融 | 只用 direct 数据训一版 vs 三种问法混合训一版，交叉测试 | 单问法训练能不能迁移到其他问法（回应第 3.2 节的风险） |
| A3 | 数据配方消融 | 不配平 vs 配平；预筛伪标签 vs 纯人工标签（伪标签须高置信+抽检） | 数据配比怎么影响结果 |
| A4 | 原生 vs 外挂对比 | Qwen3.5 原生多模态小模型（2B/0.8B）重复 A1 | lawson 最初的架构对比问题 |
| A5 | RL 进阶（SFT 之后） | 用可验证奖励（答对给分）做 GRPO，rank 16 | LoRA 做 RL 极省容量，值得试 |
| A6 | 视觉侧消融 | 给视觉编码器也加 LoRA，或只训 projector | 微调到底要不要碰视觉（呼应那支 B 站视频的观点） |

**执行顺序**：A1 → 评估 → A2/A3（消融）→ A4/A6（换模型、碰视觉）→ A5（RL）。每跑完一个实验写小结进 `docs/`。

## 7. 给训练服务器 agent 的交接说明

1. 训练数据由生成脚本产出：`scripts/make_sft_data_v2.py`。输入是标注文件 `annotations.jsonl`（标注页面导出）+ 帧目录，输出 train/test jsonl。
2. jsonl 里的 `image` 是绝对路径，来自数据准备机（Windows + WSL + E 盘）。新设备先跑脚本里的路径替换（把旧前缀换成新设备的帧目录），再开始训练。
3. 图片数据不在 git 仓库里（太大）。需要的数据：标注池全部图片 + `annotations.json` + `manifest.json`。由 lawson 手动拷到新设备，路径写进 `docs/12-本机标注阶段记录.md` 的更新版。
4. 训练用 LLaMA-Factory 或自写 Trainer 均可，但 LoRA 配置必须遵守第 4 节配方表——那是本方案最重要的外部经验输入。
5. 每次训练的输出：模型权重（存服务器本地）、测试集评估结果（json + 混淆矩阵图）、训练日志。评估结果提交回 git 仓库 `results/` 目录。

## 8. 参考资料

- Thinking Machines Lab《LoRA Without Regret》（2025-09，Schulman 等）：LoRA 在中小数据 SFT 下可与全参数微调持平；关键条件是 LoRA 覆盖 MLP 层、学习率约 10 倍、有效批次 ≤32。
