# 实验：AI 合成图像可行性测试（iter1~iter3）

> 日期：2026-10-15
> 目的（lawson 拍板）：先把生成图调到理想状态，再测 VLM 表现、预估收益，最后决定是否正式进数据工程工作流。
> 产物位置：`E:\vlm-data\synth\`（iter1/2 为调参过程，iter3 为正式批次；图片不入 git）

---

## 1. 结论（先看这个）

**建议正式采用，带三个条件**（见第 6 节）。核心理由：

1. 合成图**能复现真实世界的幻觉**：验收合格的合成推行图，云端 qwen3-vl-plus 有 18~27% 答成「骑行」——和真实监控图上观察到的失败方向完全一致。说明合成图抓对了难点，拿来做训练数据是"给模型补它正好不会的题"。
2. 成本可接受：验收合格率约 1/3，摊下来一张可用图约 0.5~0.6 元（含生成 + 淘汰）。
3. 产量可控：要补 100 张验收合格的合成推行图，约需生成 300 张（60 元左右）、一两天的生成时间（有限速）。

## 2. 过程与关键发现

### 2.1 CLI 踩坑记录（复用前必读）

用百炼 `bl image generate` 实测踩出的坑，都验证过：

| 坑 | 现象 | 对策 |
|---|---|---|
| wan2.2-t2i-flash 提示词长度限制 | 长中文提示词直接 HTTP 400 | 它只吃短提示词；复杂提示词用 qwen-image-2.0 |
| `--prompt-extend false` 传给 qwen-image 同步模型 | 返回与提示词完全无关的"回退图"（女人脸、毛驴等，同批 4 张还一样） | qwen-image 系列不要传这个参数 |
| 提示词经 bash 函数/变量多层传递 | 同样触发无关回退图 | 用 Python subprocess 列表传参（scripts/gen_synth.py 已是这么做的） |
| 水印 | 默认右下角"AI 生成"水印 | `--watermark false` 可关（qwen-image 系列验证过） |
| 限速 | 文生图 QPM 1~2 次/分钟 | 请求间 sleep 5~8 秒；`--n 4` 一次出 4 张摊薄请求数 |

### 2.2 提示词公式（把活动正确率从 25% 拉到 84%）

**活动描述放最前面，风格描述放后面**，再加负面提示词：

```
画面中央，一名{角色}{做什么：站立、双脚走路、推行…}。{监控风格描述}。{背景}。
负面：坐在车上,骑车的姿势,脚踩踏板,摆拍,艺术写真
```

- 第一轮（风格在前、无负面词）：推行正确率 25%（生成器爱画"骑行"——和 VLM 的幻觉方向一致，挺讽刺的）。
- 第三轮（活动在前 + 负面词 + 六种角色轮换）：推行正确率 84%（16 张推行候选过 11），骑行 100%（16/16）。

分场景看产量：**电动车推行 8/8 全对，自行车推行只有 3/8**（生成器老把人画成坐在车座上滑行，正好是我们标注体系里的"不确定"类）。正式量产建议主攻电动车推行，自行车推行换提示词再试。

### 2.3 监控化后处理

脚本 `scripts/synth_cctv_style.py`：缩放到 1280×720 → 轻模糊 → 降饱和偏绿 → 加噪点 → 压对比 → 暗角 → JPEG 压缩（q=70）。

**效果：有监控感但仍一眼能看出是"处理过的好照片"，和真监控的差距还在。** 且本轮实验里监控化版把推行的误判从 2 张变 3 张（11 张里），说明**重度噪点/模糊会毁掉"脚的位置"这类关键细节**。正式用时建议出两档强度（轻/重）当消融变量，不要一刀切。

## 3. VLM 测试结果（云端 qwen3-vl-plus，直接问法）

54 张图（27 张目检合格 × 原图/监控化两版）：

| | 推行图答对率 | 骑行图答对率 |
|---|---|---|
| 原图 | 9/11 = 82% | 16/16 = 100% |
| 监控化 | 8/11 = 73% | 16/16 = 100% |

- 错误方向全部是「推行 → 骑行」，与真实世界幻觉同向。
- 错误集中在"半跨姿势"的系列（人一条腿跨在车上推行，蓝衣男系列 3 张错）——这正是最难、也最真实的推行姿态。
- 骑行图 100% 答对 → 合成骑行图对训练基本是"简单题"，价值低；**合成数据的价值集中在推行侧**。

## 4. 收益预估

- 真实金标推行图只有 80 张（人标的，最贵重的数据）。合成推行图验收合格率约 1/3，**每 60 元大概能补 100 张验收合格的推行训练图**，且自带"云端模型会错"的难例属性。
- 它替代不了真实图（风格差距仍在），定位是**推行类的增量难例**，不是主力。
- 最终收益要用 A1 主实验 + 消融（真图 vs 真图+合成图）来证实，这部分在新设备上跑。

## 5. 风险与对策（正式采用的前提）

1. **风格差距**：生成图再处理也不像真监控。→ 合成图标记 `source=synth`，只进训练集，永进测试集；训练占比 ≤30%。
2. **标签可靠性**：生成器会画错姿势（自行车推行 62% 不合格）。→ 必须人工目检，以看到的实际内容为准打标（本实验每张都经我目检）；量产时 lawson 抽 10% 复核。
3. **画质退化毁细节**：监控化重档可能毁掉判断关键。→ 轻/重两档都做，进消融。
4. **多样性风险**：提示词模板就那几套，图会同质化。→ 量产时扩角色/天气/时段/路段模板库，且控制同一模板产出占比。

## 6. 建议决策

**正式采用为"推行类难例补充"生产线**，优先级排在难例挖掘和图像编辑增强之后（那两条更便宜更稳）。量产前先做的事：

1. 按 2.2 公式扩写提示词模板库（时段、天气、路段、角色到 20+ 套），自行车推行单独调。
2. 监控化出轻/重两档。
3. 先产 100 张推行图走通"生成→目检→打标→入池"全流程，再决定放量。
